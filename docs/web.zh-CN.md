# 本地 Web 界面

状态：**浏览、编辑与命令行**。界面渲染的结果与命令行一致，且页面可以运行写入类命令：命令自身的门（`--write`、工程目录限制、
原版作用域规则）决定是否真的写入，因此被拒绝时的读法与在命令行里完全一致（[cli.md](cli.zh-CN.md) §4.1–§4.3）。写入这一侧
由三个页面覆盖：`/edit` 列出一个文档的全部字段并给每行一个输入框，`/ops` 把每条写入命令做成表单并在写入前加一步检查，
`/log` 显示事件日志并带撤销与重做表单（§2.1）。仍然缺失的是写入前的语义差异、冲突检测与权限指示器。

整个界面由 Python 标准库提供——不新增依赖、没有构建步骤、不引外部资源、不设 cookie。每个页面都是
服务端渲染的 HTML，因此这第一部分在任何能显示表格的浏览器里都能用，也没有会失步的客户端状态。

## 0. 工作台

每个页面都按工作台布局，也就是生产力工具的那种形状：菜单栏、工具栏、左侧工程树、中间文档、右侧属性栏、
底部输出栏，最下面一条状态栏。

| 区域 | 内容 | 由谁填 |
|---|---|---|
| 菜单栏 | 全部分区、当前作用域、语言切换、退出 | `nav_bar` |
| 工具栏 | 每个面板一个折叠按钮，加上标签页没有的分区 | `Handler.tool_bar` |
| 标签页 | 已打开的分区；点击时由脚本换掉中间面板，不重新加载页面 | `Handler.section_tabs` |
| 左侧树 | 工程的文档按目录成层，每个目录带文件数，上方有一个按路径搜索的搜索框；纯文本表与实体文件并列 | `Handler.pane_tree` |
| 中间 | 当前打开的分区 | 各 `page_*` 方法 |
| 右侧属性 | 作用域信息，以及本次请求所指文档的字段，每个字段带进入编辑的入口 | `Handler.pane_props` |
| 底部输出 | 本次会话最近一条命令及其输出，然后是事件日志的末尾若干条 | `Handler.pane_output` |
| 状态栏 | 作用域、最近一次体检的计数、语言，以及这个页面是怎么生成的 | `Handler.status_bar` |

各面板是 CSS grid 的具名区域，之间的分隔条是拖动把手。面板宽度、折叠状态与语言是浏览器里唯一保存的东西，
存在 `localStorage["ff.workbench"]`。禁用脚本时每个页面照常可用：没有内容由脚本生成，因此拒绝脚本的浏览器
看到的只是朴素一些的工作台，而不是坏掉的页面。

页面恰好带一个内联 `<script>`，就是工作台本身（§3）。没有需要下载的外部文件，
`tests/test_web.py` 对每条路由都断言这两点。

左侧树与右侧属性读的是 `list`、`get` 两条命令返回的同一份载荷，显示的内容与命令行打印的一致。
属性栏跟随请求所指的文档，取自 `path=` 或 `selector=`；两者都没有的页面停在作用域摘要。
树的头两层默认展开，每个目录最多画 40 个文件，折叠不需要脚本。树的上方是一个搜索框：在其中输入即按路径过滤
已画出的文件，不需要往返；回车则把同一个问题交给服务端，因此单靠 `?q=` 也能在无脚本的浏览器里过滤页面
（`q` 是页面参数，不会传给任何命令）。搜不到时页面如实说明，并给出到列表页的同一查询，由命令自身的 selector
过滤作答。

状态栏由每个作用域每次加载的一次 `check` 喂养，结果在内存里保留 `CHECK_SECONDS`，因此页面之间
来回走动不会反复扫描工程。它给出该命令报出的文件数、加载错误数与悬空引用数，并各自附上取数的时刻；
作用域读不出计数时如实说明。底部输出栏开头是本次会话最近运行的一条命令——命令行、输出、退出码、
耗时，以及再跑一次它的链接——并在会话切到别的页面时保留。它下面就是事件日志的末尾，因此页面里发生的
写入紧挨着引起它的那条命令出现。

从页面发起的写入在事件日志里记为 `web`（`log actor=` 接受 `cli`、`mcp`、`web` 三个取值），
因此日志能说明改动来自哪一面。页面给出的 JSON 链接从不写入：命令行里带 `--write` 时它会补上
`--dry-run`，因此一个读起来像只读的链接不会把工程改第二次。

## 1. 运行

```
python -m core.cli <作用域> web [key=value ...]
```

| 选项 | 默认 | 含义 |
|---|---|---|
| `root=` / `workspace=` | 与其他命令一致 | 要浏览的作用域 |
| `port=` | `8765` 起的第一个空闲端口 | `127.0.0.1` 上的 TCP 端口；显式指定则要么用它、要么失败，绝不落到别处 |
| `token=<文本>` | 空 | 要求每个 URL 都带 `?t=<文本>` |
| `pagesize=` | `200` | 每页行数 |
| `lang=` | `zh` | 界面语言，`zh` 或 `en`（见下） |
| `browser=1` | 关 | 绑定后打开默认浏览器 |
| `--json` | 关 | 服务停止时打印 `{scope, root, url}`（启动横幅里已有同一地址） |

它只绑定 `127.0.0.1`，一次处理一个请求，阻塞到 Ctrl-C **或任意页面上的「退出」被确认**；绑定失败按错误报告，不
抛栈。地址在启动时打印，每个请求记录到 stderr：

```
Firefight 模组编辑器 Web UI · 作用域 Firefight
  根目录   <游戏目录>
  地址     http://127.0.0.1:8765/
  实例记录 <编辑器文件夹>\EditorCache\web.json
  页面     服务端渲染，一个内联脚本只负责工作台布局
  停止     Ctrl-C，或页面上的「退出」
  GET / 200 (312 ms)
```

示例：

```
python -m core.cli Firefight web "root=<游戏目录>"
```

### 界面语言

页面的撰写语言是中文，也是默认语言。`lang=en` 让同一批页面以英文渲染，任意页面都可用
`?lang=` 指定另一种语言；该页每个链接都会带上这个语言，选择因此在翻页中保留。导航栏里有同一个链接，
名称为 `English` 或 `中文`。启动横幅同样跟随 `lang=`。页面上 `lang=` 写了服务不认识的语言时返回 `400`。

服务打印的每一条文本都经过同一张表（`core/web/i18n.py`），并有用例断言该表覆盖全部条目：新增页面而
忘记写措辞时，测试会失败，而不是在英文模式下静默显示中文。

若不想占住提示符，用包装命令行的本地启动器（`tools/launcher/ff-tool.ps1`，发行版里是 `launcher/`）：
`ff-tool.cmd web -Window` 把服务**隐藏在后台**启动——不留控制台窗口——并用自己的独立应用窗口打开页面
（`msedge --app=<url>`：没有标签页、没有地址栏，是窗口而不是浏览器会话）；`-Browser` 强制使用普通浏览器窗口，
`-NoBrowser` 什么都不打开。发行版里的 `StartWebUI.cmd` 默认就走这条路径——`-Foreground` 改为在控制台里服务——
`-Scope <名称>` 选择服务的作用域，因此双击总是得到独立窗口和下面的看门狗。

端口一有响应调用方就返回；服务输出写到启动器日志旁边的 `logs\web-<port>-err.log`，不必留着窗口才能看。
`status` 显示服务进程与那份日志，`stop` 结束进程并清除记录的状态。不给端口的窗口不会因端口被占而失败：它先复用本
编辑器已记录的实例，否则取 8765 及以上的第一个空闲端口（[cli.md](cli.zh-CN.md) §4.4）。`-Port <n>` 保留更严格的旧
规则——要么用该端口，要么被拒绝——因此显式指定不会悄悄落到别处。由于什么都不用留着，停止界面的方式就是页面上的
「退出」按钮和启动器的 `stop`。

**忙端口拒绝**是主动要求的，不是继承来的：`HTTPServer` 会设置 `SO_REUSEADDR`，在 Windows 上这会让第二次绑定
一个已在服务的端口成功，于是两个界面会悄悄共用同一端口、谁应答全看运气。因此 `make_server` 先探测端口
（`socket.connect_ex`），占用时抛 `cannot listen on 127.0.0.1:<port>: the port is already in use`。端口 `0`
（测试用的）总能拿到空端口。不给端口的 `web` 不会走到这个错误：它向 `free_port` 要 8765 及以上的第一个空闲端口，
因此默认端口上留着别的服务不再妨碍界面启动。

后台会话会带一个隐藏的**看门狗**，双向工作：

* **服务先停**——`退出`、`stop`、Ctrl-C 或崩溃：它检查停止方式（进程是否消失、端口是否释放、服务是否在日志里留下
  正常退出的标记），关闭自己打开的应用窗口、删掉该窗口的临时浏览器 profile，然后退出。结论追加到
  `logs\web-<port>-exit.log`（`graceful True/FALSE` 加 `backend exited normally` 或某种失败描述），`status`
  以 `last session` 报告它。会话里点「退出」读到 `backend exited normally`；用启动器 `stop` 停掉的读到
  `graceful False ... (killed?)`，因为 `stop` 是结束进程而不是礼貌询问。
* **窗口先关**——它会礼貌地请服务停止（`/quit?do=1`，日志里仍读作 `backend exited normally`），而不是留下一个
  没人看的服务在跑。存活信号取自窗口的 **profile 锁**：加了 `--user-data-dir` 后，浏览器在窗口存续期间一直持有
  该目录下的 `lockfile`，这比「浏览器把窗口交给别的进程」更可靠。`Start-Process` 返回的 pid 与浏览器进程数量都
  不可靠——两者都实测会骗人。启动器最多等 15 秒拿这个锁，拿到才认为会话受监视；窗口一直没出现就明确说明并让服务
  处于不受监视状态，而不是半监视。判死要连续三次检查（约 5 秒）都失败才采信，因此启动慢的浏览器不会误杀活会话。

`-Browser` 在用户自己的浏览器里打开页面：那个窗口永不被监视也永不被关闭，因为它不属于启动器。`-NoBrowser`
什么都不打开，也就没有可监视的对象。

运行中的服务记录在 `<编辑器文件夹>/EditorCache/web.json`，识别不出编辑器文件夹时记录在工程目录下，字段为 `pid`、
`host`、`port`、`url`、`scope`、`token` 与 `started`。正是这条记录让第二个 `web` 复用第一个，而不是另起一个竞争的
服务。`serve` 在端口开始应答后写入它，并在正常停止时删除；被强杀的进程会留下陈旧记录，此时由其地址的探测结果决定，
因此崩溃过的界面不会阻塞下一次启动。启动器读同一个文件来取得要打开的地址，它的进程归属检查则把记录中的 `pid` 与正
在应答该端口的进程比较——按命令行匹配实测不可靠（受限会话里 `Get-CimInstance` 被拒绝），而归属判错会留下一个没有
窗口的服务，并把实际属于自己的端口报成被他人占用。

## 2. 页面

| 页面 | 路由 | 内容 |
|---|---|---|
| 首页 | `/` | 作用域、根目录、来源、计数，以及指向各处的链接 |
| 实体列表 | `/list` | 全部实体及类别、格式与大小；可用 `prefix=`、`type=` 过滤，`page=` 翻页；每行带编辑、复制、删除三个入口，页面另带新建文档表单（§2.3） |
| 实体详情 | `/show` | 一个实体的 `as=toml`（默认）、`as=xml` 或 `as=raw`，以及它的入向与出向引用 |
| 读取字段 | `/get` | 文档路径处的 `field=<a.b.c>` |
| 查找 | `/find` | `tag=`、`value=`、`path=`、`ignore_case=1`；需要选择范围 |
| 引用 | `/refs` | 一个文件指向什么，按类别分组 |
| 反查 | `/deps` | 谁指向 `value=<令牌>`；并显示该令牌解析到了什么 |
| 体检 | `/check` | 加载错误、警告与悬空引用；`selector=` 缩小范围 |
| 统计 | `/stats` | 按类别、根元素与存储格式计数 |
| 编辑 | `/edit` | `path=<文档>` 的全部字段，每行一个输入框（§2.1） |
| 源码 | `/source` | 一份文档的整段文本，TOML 或 XML，整体保存（§2.5） |
| 日志 | `/log` | 事件日志，可按 `document=`、`field=`、`actor=`、`result=`、`since=`、`until=` 过滤，并带撤销与重做表单 |
| 操作 | `/ops` | 每条写入命令做成表单，写入前有一步检查（§2.1） |
| MCP | `/mcp` | MCP 工具表、连接片段、在进程内试跑一次 `tools/call`，以及可选的 HTTP 监听（§2.6） |
| 资源 | `/assets` | 工程的图片与声音，直接由文件本身绘制（§2.2） |
| 表格 | `/tables` | 工程设置声明的纯文本表，每行一条，可改、可删、可追加（§2.4） |
| 命令行 | `/cmd` | 一行命令，按输入执行，按命令行的方式打印（`line=`、`json=1`） |
| 帮助 | `/help` | 命令行参考与页面清单 |
| 退出 | `/quit` | 先确认，再停止服务（`/quit?do=1`） |
| `/json?command=<cmd>&selector=<sel>&…` | | 原始 `--json` 载荷，`text/plain` |
| `/asset?path=<文件>` | | 一个工程文件本身的字节，带内容类型与 `ETag`（§2.2） |
| `/tables?path=<文件>` | | 一张已声明表格的各行，及其编辑表单（§2.4） |
| `/source?path=<文件>` | | 一份文档的整段文本与保存表单（§2.5） |

每个结果页面还会打印等价命令（`python -m core.cli Firefight list all --json`）并链接到自己的 JSON，因此屏幕上的
内容总能从 shell 复现。

`/cmd` 是同一思路的延伸：一个文本框接收 `python -m core.cli` 之后的部分（`list weapon`、
`show Data/Weapons/WEAPON_PISTOL_P38.txt as=toml`、`deps value=WEAPON_PISTOL_P38`），可选地在最前面写作用域名，
带空格的路径用双引号。页面打印命令自身的文本输出，或用 `json=1` 得到载荷，另外给出退出码、耗时与等价的 shell 命令。
它跑的是与命令行相同的解析器与处理函数，因此输出不是重新渲染——有测试比较 `<pre>` 块与 `Result.text`。`web` 在
`/cmd` 与 `/json` 上被拒绝，因为它会在一次请求里尝试绑第二个端口（别名 `serve` 同样被拒）。其余命令都不被拒绝：
`set`、`convert` 与 `export` 在页面上的行为与在 shell 里一致，是否真的写入由它们所指命令自身的门决定。

每个页面顶栏都有「退出」链接。它指向确认页而不是直接停止，因为界面是纯 GET：链接可能被预取或被误点，而第二次有意
点击不会。确认后服务停止（后台线程在告别页发送完后停止 `serve_forever`）；已打开的数据文件与游戏安装不受影响，
只是本地服务进程结束。

### 2.1 写入类页面

`/edit` 取 `path=<文档>`，列出该文档的全部字段，一字段一行，每行有自己的输入框与自己的「保存」按钮。字段路径就是
`get` 打印的那种（`ammo.type.0.name`），因此从这里复制的路径可以原样用在命令行上。这一行本身不写入：它的表单以
`command=set`、该文档、该字段路径与新值提交到 `/ops`，所以从本页保存与其它写入走同一步检查。本页还链到 `/ops`（需要
多于一个选项的改动）与 `/log`。

`/ops` 把整个写入侧做成表单：`set`、`batch`、`add`、`clone`、`remove`、`index`、`convert`、`settings`、
`roster`、`export`、`pack`、`init`、`import`、`undo` 与 `redo`——十五条能改动的命令。不给 `command=` 时是一张表，
每条命令一行链接，写明它做什么、是否取文档；给出命令则显示
它的表单。字段来自该命令自己的选项，因此复选框就是开关（`overwrite=`、`assets=`、`strict=`），下拉框就是枚举（`set` 的
`op=` 是 `append`/`delete`，`settings` 的 `op=` 是 `render`/`emit`，`roster` 的 `op=` 是 `add`/`set`/`remove`）。
`undo` 与 `redo` 的条数填在文档参数栏，因为那个条数是命令的位置选择项而不是选项。

第一次不会写入。带 `confirm=1` 时页面打印等价的那行 `ff` 命令，然后打印真正以 `--write --dry-run` 运行它的结果——这正是
它能承诺「什么都没落盘」的依据；随后一个带 `write=1` 的「写入」链接才真正执行。检查一步给的是 `write=1 dry-run=1` 而不是
单独的 `--dry-run`，因为每条写入命令都取 `--write`，真正拦在磁盘外的是 `--dry-run`（[cli.md](cli.zh-CN.md) §4）。当命令
拒绝这次检查时——`undo` 没有可撤销的事件、`init` 撞上已有工程、`add` 的目标不是可处理的文档——页面把那次拒绝显示为检查
结果，并且不给写入链接，因为写入会以完全相同的方式被拒绝。分成两步的原因是界面只开放 GET：链接可能被预取或误点，而写入
与「它会做什么」之间应隔着一个明确的点击。最终仍由命令自身的门拍板。

检查步骤跑 `set` 时，页面先给出一张差异表——文档、字段路径、现在的值与操作后的值——再接原始输出。原始输出是命令
自己的答复，这张表只是对它的解读；命令以别的形态报告空跑时，这张表就不出现。

写入链接携带检查步骤记录的摘要（`expect=`）。写入时拿它与链接被点开时的文档重新比对，不一致就拒绝，因此检查之后被
别人改过的文件不会被基于旧判断覆盖；页面会说明这一点并要求重新检查。命令行侧有同样的保护：计划只在文档仍是当初被计划
的那一份时才应用（[cli.md](cli.zh-CN.md) §4）。

`/log` 打印事件日志，带 `log` 命令支持的过滤条件，并在旁边给出撤销与重做表单；这些表单通向 `/ops`，因此撤销与其它写入
一样要先过检查。

### 2.2 资源

`/assets` 遍历工程的 `Images/` 与 `Sounds/` 两个目录，画出浏览器自己能渲染的东西：图片变成缩略图，点开看原尺寸；声音
变成播放器。浏览器不认识的扩展名一律跳过，所以恰好放在 `Images/` 里的 `.txt` 不会被当成图片摆出来。`folder=Images` 把页面
收窄到一个目录。每个目录最多画 60 个，页面同时说明总数；本机实测最大的工程（866 张图片、70 个声音）约 170 毫秒渲染完。

字节来自 `/asset?path=<文件>`，一条页面集之外的只读路由。它把路径解析到工程目录下，任何越出工程目录的写法都拒绝，所以
`../`、绝对路径与盘符会被当作文件不存在，而不是被读出来；目录与不存在的文件同样拒绝。响应带文件自身的内容类型，以及由
大小与修改时间拼出的 `ETag`，因此浏览器带 `If-None-Match` 再来一次会得到 `304`，没变的图片不会重发一遍。

同一条路由支撑属性面板：当所选文档有字段的值指向工程内真实存在的图片或声音时，该字段的预览会出现在字段表下方。指向
不存在的值不做处理——那是工程尚未填上的引用，`check` 已把它报为悬空（[refs.md](refs.zh-CN.md)）。

### 2.3 实体数据框

`/list` 是三个文档级写入挂靠的数据框：每一行带 改（`/edit`）、复制（`/ops?command=add&from=<该文档>`）与
删除（`/ops?command=remove&selector=<该文档>&confirm=1`），页面另带一张新建文档表单，以路径与可选的复制来源运行
`add`。`add` 不给 `from=` 时按 schema 建骨架，给了就复制那份文档。

三个写入里只有第一个直达目标页。复制与删除通向操作页的检查步骤，而删除带 `confirm=1`，页面打开时检查已经跑过：
屏幕上就是该文档 `--write --dry-run` 的真实结果，写入还要再点一次。因此数据框是入口而不是第二条写入路径——它给出的
每个动作都落在与命令行相同的那一页、相同的门上。

字段级编辑在 `/edit`（§2.1），它列出一个文档的全部字段、每字段一个输入框；数据框负责把人带到正确的文档。

### 2.4 纯文本表

`equipment_*.txt` 与 `surnames_*.txt` 既不是 XML 文档也不是 TOML：每行一个条目，`//` 起头是注释，文件既没有根
元素也没有 schema。命令行把它们当作清单文件跳过（[cli.zh-CN.md](cli.zh-CN.md) §4.3），因此在本次之前，编辑器里
没有任何办法改动其中之一。

`/tables` 补上这一处。它读工程设置——有 `<工程>/mod.txt` 就用它，否则用 `ModSetting.toml`，与
`declared_lists` 读的是同一对——列出被声明的表格，以及 `Data/` 下其余清单文件。打开一张就按原顺序列出每一行、
每行一个输入框、每行一个删除入口，末尾再给一张追加表单。

写入不走任何写入命令。没有写纯文本表的命令，这个页面也不新造一条：它用 `core/web/tables.py` 拼出新的文档文本，
交给 `core.edit.plan_render` 与 `core.edit.apply_document`——与其他所有写入相同的那对「先计划、后应用」。因此这条
记录会带 `actor=web`、前后字节数与两个摘要进入事件日志，`undo` 会把文件按字节还原。`web` 正是为此加进
`core.journal.ACTORS`：日志说明是哪个交付面写的，`log actor=web` 回答页面改了什么。

一行沿用文档原本的换行，注释从不计入行号，删除会留下多余的换行而不重排整个文件。注释与空行只显示为标记，永远不是
可编辑条目。

检查步骤同时给出该行现在与操作后的样子，写入链接携带检查读到的文件摘要，因此其间被别人从命令行改过的表格会被拒绝而不是
被覆盖（§2.1）。

### 2.5 源码页

`/edit` 一次改一个字段，对于没有 schema 的文档、或需要整体重排的文档，这个形状并不合适。`/source` 把整份文件放进一个
输入框，再整体写回。它只打开工程内的 `.xml`、`.toml` 与 `.txt`，其余后缀一律拒绝；路径在工程目录内解析，`../` 与绝对
路径都会被拒。

保存保留文件自己的编码、BOM 与换行：带 BOM 的文件按 `utf-8-sig` 写回（`textio.encode_export` 自己从不加 BOM）。写入
经 `core.edit.plan_render` 与 `core.edit.apply_document`、以 `actor=web` 记账，与表格页完全相同，因此会进事件日志、
可被 `undo` 还原。

写入前后页面都会对该文档跑一次 `check` 并打印结果，但从不因此拦截——读不出来的文档正是有人来这里要修的那份。保存仍是
与其他页面相同的两步：先检查（不落盘），再写入。检查步骤会给出文件现在与写入后的行级差异，写入链接携带计划所依据的
摘要（§2.1）。

有一处限制来自界面而非编辑器：界面只支持 GET，被编辑的文本走查询字符串，因此超过 16000 字节的文件会被拒并写明这个数字。
随附的所有文档都远低于它。

### 2.6 MCP 面板

`/mcp` 是唯一不调用命令行命令的页面。它读的是 MCP 服务与 DSH 插件读的同一张工具规格表
（`core/cli/specs.py`），因此屏幕上显示的名称、命令与参数就是客户端收到的那一份；它还打印接上本工作区的两条命令行与一段
客户端配置。

试跑在进程内跑一次 `tools/call`，经 `core.mcp.server.Server`，把 JSON-RPC 应答原样打印：不开套接字、不另起进程、不走
stdio。名字不是服务登记的工具时返回的就是错误应答，与客户端所见相同。

写入类工具走与 `/ops` 相同的两步。除非请求带 `write=1`，试跑会自动补上 `dryRun`，因此检查步是「写入的门开着、dry-run 的
门在起作用」的那一行；页面如实说明，并给出按原样执行的链接。以这种方式发生的写入经 `core.mcp.tools`、以 `actor=mcp` 记入
与其他写入相同的那本日志，因此页面写不出命令行写不出的东西。

面板还可以另开一个套接字（`core/web/mcp_listener.py`），供只走 HTTP 而非 stdio 的 MCP 客户端使用。这个监听在表单打开它
之前一直是关的，绑定本进程内的一个地址与一个端口——`127.0.0.1` 只给本机、`0.0.0.0` 给局域网——并带一个开监听时生成的
自有令牌，页面把它打印出来，客户端以 `X-Ff-Token` 头发送。开监听是真实的绑定，因此端口被占用时如实拒绝并给出原因，
而不是悄悄换端口；关闭时立即释放套接字。不带写入开关时，它登记的工具与命令行上不带 `--write` 的服务器相同，即那八个
只读工具。该套接字一次应答一条 POST 的 JSON-RPC 消息，不提供别的东西：不是消息的请求一律拒绝，令牌缺失或不对时在读
请求体之前就拒绝。

## 3. 设计规则

* **同一套实现。** 页面在同一个进程里调用命令行调用的同一处理函数（`cli.commands` 加已解析的 `Context`）。界面
  不会与 `python -m core.cli --json` 漂移；有测试断言 `/json` 载荷与命令行打印的内容一致。
* **只有一段短脚本，别无其他。** 每个页面恰好带一个内联 `<script>`，即工作台本身：它调整与折叠面板、把面板宽度
  记进 `localStorage`，在点标签页时换掉中间面板，并在搜索框里输入时过滤左侧树。它不生成任何内容，因此禁用脚本时
  页面依然完整可读；它只向本服务发请求，因此没有外部资源、没有 CDN。测试会走遍每条路由，断言恰好一个 `<script>`、
  没有 `<script src`、也没有 `<link`。
* **老式朴素 HTML。** 一个内联 `style` 块、灰底、带边框的表格、数据用 `<pre>`。没有框架、没有下载的字体、没有图标、
  没有 CDN——离线渲染结果一致。字体走系统栈——窄体工业无衬线（首选 `Tahoma`，回退 `Arial Narrow` 与平台无衬线）——
  基准字号 15px，观感接近桌面工具而不是网页。
* **只用 GET。** `POST` 返回 `501`。唯一会结束本服务进程的路由是 `/quit`，且它在确认后才那么做。`/cmd` 与 `/json`
  拒绝 `web` 及其别名 `serve`，因为它会在一次请求里尝试绑第二个端口；其余命令都在那里运行，写入类命令也一样。页面
  从不自行决定发生写入：它把拿到的选项交给命令，由命令自身的门作答。
* **每连接一个线程。** 服务是 `ThreadingHTTPServer`（守护线程，关闭时不等待它们）。浏览器会开推测性连接并让它们
  空着；单线程服务会卡在这种 socket 上读一个永不到来的请求行，其他请求全部排在后面，看起来就像页面卡死。
* **端口被占就拒绝。** `make_server` 在绑定前探测端口，因为 `SO_REUSEADDR`（默认开启）在 Windows 上会让第二个
  服务绑定已在服务的端口。一个端口一个界面，或者给出明确错误。
* **表单保留作用域与令牌。** `GET` 提交会用表单自身的控件替换 action 的查询串，因此 `server.form` 把 action 的
  参数（`scope`、`t`）搬进隐藏输入，把 action 留成裸路径。没有这条规则时，非默认作用域上的表单会悄悄去搜原版数据，
  设置了令牌后所有表单都回 `400`，`/quit` 的确认表单也会一直追问而不退出。
* **默认转义。** 每个插值都经过同一个转义助手，文本与属性值都一样；有测试把 `<script>` 塞进列表文件与 TOML 视图，
  证明它仍然是文本。
* **输出有界。** `pagesize=` 限制列表、查找、引用与反查的行数；页面说明省略了多少行并链接到完整 JSON。
* **输入不可信。** 选择器是绝对路径、以 `~` 开头、带盘符或含 `..` 段时，在任何命令看到它之前就被拒绝。

## 4. 限制与安全

* 它是本地游戏安装的编辑器，不是服务器：只放在 `127.0.0.1`。`token=` 用于「本机其他用户或进程可能访问该端口」的
  场景。
* 没有 TLS、除共享令牌外没有认证、没有用户账户、没有限流。
* 长时间扫描是同步的，各占一个工作线程：对整个原版作用域跑 `check` 与在 shell 里跑同样耗时（数秒），期间其他请求
  由各自的线程处理。
* `Mod` 作用域仍需要 `ModInformation.toml`（或 `root=`）；界面不会凭空造出工程。

## 5. 测试

```
python -m unittest tests.test_web          # 150 条，约 32 秒
python -m unittest discover -s tests -t .  # 跑全套
```

`tests/test_web.py` 会建一个小型示例工程（`tests/_scratch_web/`）并在端口 `0` 上启动真实服务，因此测试覆盖解析、
转义、分页、令牌、`404`、`POST`/`PUT`/`DELETE`（都返回 `501` 且读完请求体）、目录穿越尝试、JSON 视图、每个页面上
的「退出」链接、按浏览器方式提交的确认表单、确认后的停止、命令行（文本输出等于 `Result.text`、JSON 复选框、带引号
的路径、作用域前缀、未知命令，以及 `web`/`serve` 在 `/cmd` 与 `/json` 上被拒绝、而写入类命令可以通过）、页面发起的
写入到达命令自身的门（不带 `--write` 的 `set` 以 `set needs --write` 被拒，文档保持不变），以及实例记录（应答中的实例
被复用、陈旧的被忽略、正常停止时删除）。写入类页面另有自己的用例：`/edit` 列出一个文档的全部字段且每行一个输入框，并把
保存链到 `/ops`；`/ops` 列出十五条写入命令，每一条的检查步都会作答（哪怕表单什么都没填）；一张表单不会把同一个参数写两遍；检查一步以
`--write --dry-run` 运行、工程无改动、打印等价的那行 `ff` 命令、不给 `write=1` 链接；拒绝检查的命令不给写入链接并显示该
拒绝；`write=1` 随后真的改动文档、追加事件，并让 `/log` 显示它，撤销亦然；对带悬空引用的工程执行 `pack strict=1` 被拒且
不给写入链接；字段编辑器拒绝没有字段、没有值的 `set`，并在表值路径上要求直接给出该条目；表单能穿过语言切换，被指定过
语言的链接会保持该语言；`/tables` 列出已声明的纯文本表且每行一条、把注释与空行标成标记而不供编辑、可追加可编辑可删除、
在给出写入链接之前先说明检查会写什么、把超出文件范围的行号报为错误、拒绝工程外的路径、以 `actor=web` 经 `core.edit` 写入
（日志记的是页面而不是命令行，撤销会把文件还原）；`/source` 把一份文档当整段文本打开，未给路径前不列出任何东西，拒绝它
不编辑的后缀、拒绝工程外的路径、拒绝超过上限的文件并写出该上限、报告只检查不写入、把带 BOM 的 UTF-8 文件连着 BOM 写回、
把 CRLF 文件连着 CRLF 写回、文本没有变化时不给写入链接，并把改动记为 `actor=web`。检查步骤现在会先展示改动：`/ops`
打印字段、现在的值与操作后的值，`/tables` 打印该行现在与操作后的样子，`/source` 打印行级差异；而在检查之后磁盘上的文档
被改过时，跟随写入链接会被拒绝，另一个写者写入的字节原样留在文件里。MCP 面板另有自己的用例：`/mcp` 列出
规格表里的每一个工具并打印命令行与客户端配置块；只读试跑给出 JSON-RPC 结果且不是错误；服务未登记的名字与不是 JSON 的参数
都如实报出；写入类工具在补上 `dryRun` 的情况下试跑，因此检查步什么也没有写，同时给出按原样执行的链接——跟随该链接会写入
文档，并在日志里留下一条 `actor=mcp` 记录。工作台外壳另有最后一组用例：每个页面恰好带一个内联脚本、
不加载别的任何东西；页面可以只请求中间那一栏；状态栏带上真实 `check` 给出的文件、错误与悬空计数并注明取数时刻；
输出栏起初没有命令，之后在页面之间保留最近一条命令及其输出、退出码、耗时与再跑一次的链接；从 `/cmd` 或 `/ops`
发起的写入在日志里记为 `web`，而来自别的 actor 的同一次写入不会；写入的那行命令给出的 JSON 链接带 dry-run，
因此跟随它不会改动文档，也不会留下记录。监听另有一组用例：面板打开它之后，真实 MCP 客户端用页面打印的令牌经 HTTP 取到
只读工具表；只有表单要求时才出现写入类工具；端口被占用时报用法错误且不留下任何监听；既不是 `local` 也不是 `lan` 的地址
被拒绝；套接字用监听自己的令牌应答 POST、缺少令牌时在读请求体之前拒绝、`GET` 是拒绝；关闭后端口不再应答。工作台的字面与搜索框另有一组用例：基准字号与字体栈来自样式表；每个页面
都带搜索框；树为每个文件画出其路径；`?q=` 把树收窄到匹配的路径并给出计数；搜不到时如实说明；搜索框给出到列表页的
同一查询；树表单把作用域放在隐藏字段里而不是 action 里。针对原版安装实测，这第一部分每个页面约两秒应答（对整个 1840 文件的原版作用
域冷启动 `/stats` 是最慢的一次），并在分页 `deps` 视图里给出 `WEAPON_PISTOL_P38` 的 1204 条引用；`/cmd` 对 `stats`、
`deps value=WEAPON_PISTOL_P38` 与带引号的 `show` 结果相同。

## 6. 后续

编辑如今有了前端：`/edit` 列出一个文档的字段，`/ops` 提供每条写入命令并在写入前加一步检查，`/tables` 编辑命令行跳过的
纯文本表，`/source` 把一份文档当整段文本编辑，`/mcp` 展示并试跑 AI 各交付面读的那些工具。它们外面的工作台已经完整：
左侧树与右侧属性读 `list`、`get` 的载荷，状态栏带上最近一次 `check` 的计数，输出栏把最近一条命令放在事件日志末尾旁边。
仍然缺失的是生产力工具在此
之上还要加的东西——检查与写入之间的语义差异（检查给出的是命令输出，不是前后字节的对照）、两次操作之间文档被改动时的
冲突检测，以及一眼说明当前作用域与选项能否写入的权限指示器。另一处未完成的是那个能让 `refs` 与 `deps` 从
`EditorCache/index.toml` 作答、而不必每次重算引用图的索引器。
